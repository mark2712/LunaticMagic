# Архитектура и План Подсистемы Времени (Game/Time)

**Проект:** LunaticMagicV3  
**Путь:** `Assets/Scripts/Game/Time/plan.md`  
**Дата создания:** 11 ноября 2026  
**Назначение:** Описание ответственностей, механики календарного времени, паузы сессии, взаимодействия с фокусом сущностей и реализации эффекта «Сандевистан» (Bullet-Time).

---

## 1. Зоны Ответственности Подсистемы

Подсистема времени решает строго две изолированные задачи:

1. **Внутриигровой Календарь Мира (`LocalWorldGameTime`):**
   * Счётчик `WorldSeconds`, вычисление `Day`, `Hour`, `Minute` для смены суток, поведения NPC и расписаний.
   * **Тикает строго в `FixedUpdate` через `fixedDeltaTime`:**
     * Привязка к физическому тику гарантирует, что время мира шагает строго синхронно с физической симуляцией.
     * Если мир замедлен (Сандевистан) или заморожен (пауза), календарное время замедляется или останавливается абсолютно синхронно с миром, без рассинхрона из-за колебаний FPS кадров рендера (`Update`).
   * Сохраняется в файл сохранения сессии (`LocalGameTimeData`).

2. **Диспетчер Времени Движка Unity (`GameTimeController`):**
   * Управление системными движковыми свойствами: `Time.timeScale`, `Time.fixedDeltaTime`.
   * Адаптация физического шага PhysX под замедление времени с защитой от зависания (`MinFixedDeltaTime = 0.0005f`).
   * Полная изоляция от паузы: паузой звука (`AudioListener.pause`) и состоянием симуляции управляет стейт сессии (`GameSession.State`), а не контроллер времени.

## 2. Проблема Паузы Сессии и Потери Замедления

### Проблема:
Если игрок активировал «Сандевистан» (мир замедлен до `0.2f`), и в этот момент нажал `Esc` (пауза сессии):
1. Контроллер времени ставит `Time.timeScale = 0f`.
2. При выходе из паузы нельзя ставить `Time.timeScale = 1.0f`, иначе эффект Сандевистана мгновенно сбросится!
3. Также нельзя хранить единый «предыдущий scale», если за время паузы или катсцены фокус переключился на другую сущность.

### Архитектурное Решение: Вычисление через Фокус (`ITimeState`)
Контроллер времени **не хранит жестко зашитую скорость геймплея**. Скорость геймплея и режим работы времени являются **вычисляемым состоянием**, зависящим от:
1. Состояния сессии (если пауза $\rightarrow$ принудительный `PauseTimeState`).
2. Сущности, которая в данный момент находится в фокусе (`FocusManager.CurrentFocus`).

Сущность в фокусе отдает один из готовых классов-команд `ITimeState`:
* `NormalTimeState(scale)` — для боя, бега, замедления (Сандевистан `scale = 0.2f`) и фаз 1–2 сна.
* `FastForwardTimeState(scale)` — для фазы 3 сна (перемотка календаря в темноте со скоростью `scale = 100f` при замороженном PhysX).

```csharp
public interface ITimeState
{
    float PhysicsTimeScale { get; }
    float GameTimeScale { get; }
    float FixedUpdate(float fixedDeltaTime, LocalWorldGameTime worldTime);
    float Update(float unscaledDeltaTime, LocalWorldGameTime worldTime);
}
```

### Точки Пересчета Времени (`Recalculate`):
Контроллер времени пересчитывает `Time.timeScale` и `Time.fixedDeltaTime` в двух событиях:
1. **Смена состояния сессии:** переход `SystemPause` $\rightarrow$ `Gameplay` (или обратно).
2. **Смена фокуса:** `FocusManager.OnFocusChanged` (переключение с персонажа в Сандевистане на катсцену или дрона).
3. **Изменение внутри активной сущности:** сущность эмиттит событие об изменении своего желаемого `ITimeState`.

### Принцип Инкапсуляции и Безопасности Перемотки:
* **Инкапсуляция ускорения:** Ускорение/замедление — локальное дело конкретной сущности (в мире может быть много ускоренных NPC). Движковый `PhysicsTimeScale` замедляет мир **только** тогда, когда ускоренная сущность находится **в фокусе** (кинематографичный эффект для игрока перед монитором).
* **Изоляция перемотки сна:** Перемотка времени (быстрый календарь без физики) управляется **сущностью катсцены/сна**, забирающей фокус на себя. Перемотка во время управления персонажем игрока невозможна, что исключает баги ввода и коллизий.

## 3. Механика «Сандевистана»: Физика и Компенсация Персонажа

### 3.1. Управление Движком:
Базовый шаг физики Unity: `BaseFixedDelta = 0.02f` (50 тиков в секунду).
При изменении масштаба времени:
```csharp
float targetScale = isPaused ? 0f : focusedEntityTimeScale;

Time.timeScale = targetScale;

// Чтобы симуляция физики оставалась идеально плавной и не дергалась:
if (targetScale > 0.001f)
{
    Time.fixedDeltaTime = 0.02f * targetScale;
}
```

### 3.2. Ускорение Персонажа Внутри Замедленного Мира:
Поскольку `Time.timeScale = 0.2f`, движок замедляет все физические тела и аниматоры в 5 раз.
Чтобы персонаж двигался со своей нормальной (или повышенной) скоростью:

1. **Компенсатор времени сущности:**
   $$K_{\text{compensation}} = \frac{1}{\text{Time.timeScale}}$$
   *(При `timeScale = 0.2` коэффициент компенсации равен $5$)*.

2. **Локомоция (Движение в FixedUpdate):**
   Внутри контроллера движения персонажа скорость домножается на компенсатор:
   $$\text{Velocity} = \text{BaseSpeed} \times K_{\text{compensation}} \times \text{BoostFactor}$$

3. **Аниматор:**
   Анимация персонажа ускоряется в обратную сторону:
   $$\text{Animator.speed} = K_{\text{compensation}} \times \text{AnimBoost}$$

4. **Ввод и Прицеливание (Update):**
   Поворот камеры и считывание мыши работают через `Time.unscaledDeltaTime`, поэтому чувствительность обзора остаётся отзывчивой и естественной.

## 5. Режим Внутриигрового Сна и Ожидания (Sleep / Fast-Forward Pipeline)

### 5.1. Постановка Проблемы
В классических RPG (Skyrim, Fallout) при нажатии «Ждать 8 часов»:
1. **Проблема 1 (Удар по атмосфере):** Экран мгновенно темнеет, а после открытия все NPC стоят ровно на тех же местах, где были 8 часов назад, и только потом начинают разбегаться. Это выглядит неестественно («эффект манекенов»).
2. **Проблема 2 (Взрыв физики):** Если ускорить движковое время `Time.timeScale` в 20–50 раз при включённой физике (PhysX), тела начинают проваливаться сквозь стены (туннелирование), рэгдоллы улетают в космос, а FPS падает в ноль из-за расчёта сотен столкновений за микросекунду.

### 5.2. Симметричный Пайплайн Сна (Засыпание 1→2→3 и Пробуждение 3→2→1)

Для идеальной кинематографичности и ощущения «живого утра» цикл сна строится **симметрично**: как вход в сон идет через постепенное замедление чувств и ускорение мира, так и выход повторяет эти фазы в обратном порядке (эффект «открывания глаз и тяжелых век»).

### 5.3. Преимущества Решения
1. **Эффект засыпания и пробуждения:** естественный кинематографичный переход (через фазы восприятия 1 $\rightarrow$ 2 $\rightarrow$ 3 $\rightarrow$ 2* $\rightarrow$ 1*) вместо грубого щелчка по рубильнику.
2. **Живой мир:** NPC не стоят истуканами ни перед сном (успели разойтись), ни утром (уже двигаются в утреннем полуразмытом свете).
3. **Абсолютная безопасность для PhysX:** в фазе глубокой перемотки физика гарантированно заморожена, поломка коллайдеров невозможна в принципе.
4. **Бесшовная интеграция:** финал сна не требует специального кода — он использует уже спроектированный **Барьер Синхронизации**.

## 6. Итог

1. **Никакой слепой перемотки в реальном времени:** только контролируемый 4-фазный пайплайн сна.
2. **Время мира в `FixedUpdate`:** надежная детерминированная смена суток без погрешностей от FPS рендеринга.
3. **Сандевистан без багов паузы:** масштаб времени определяется текущим состоянием сессии и активной сущностью в фокусе.
