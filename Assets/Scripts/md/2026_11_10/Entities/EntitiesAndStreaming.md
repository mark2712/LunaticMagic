## 1. Реестр Сущностей в оперативной памяти

При старте сессии в память загружается облегчённый словарь всех существующих в игре сущностей:
* Содержит `EntityId`, координаты, виртуальный размер/радиус и принадлежность к спавнеру.
* Позволяет мгновенно находить сущность и отслеживать дистанцию до неё без необходимости держать её тяжелые компоненты и игровые объекты на сцене.

## 2. Пять уровней существования Сущности

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. L0 (Не загружена / Спит на диске)                                        │
│    • Есть ID, локация и координаты в общем реестре сессии                   │
│    • Детальные данные лежат в файле внутри папки сессии                     │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │ Стриминг по дистанции ИЛИ прямое обращение по ID
                                       ▼ (ЗОНА ОТВЕТСТВЕННОСТИ НИЗКОГО УРОВНЯ)
┌─────────────────────────────────────────────────────────────────────────────┐
│ 2. L1 (Загружена из файла в память / Pure Data)                             │
│    • Чистый C# класс EntityRuntime в оперативной памяти                     │
│    • Включены системы здоровья, инвентаря, A-Life симуляция вне физики      │
│    • Нет GameObject на сцене Unity, нет физики и рендера                    │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │ (ЗОНА ОТВЕТСТВЕННОСТИ ВЫСОКОГО УРОВНЯ)
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 3. L2 (Замороженное физическое тело)                                        │
│    • Легкий GameObject с коллайдером, Rigidbody.isKinematic = true          │
│    • Удерживает место в пространстве, доступен для рейкастов и триггеров    │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │ Приближение к активной зоне
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 4. L3 (Активная физика)                                                     │
│    • Rigidbody.isKinematic = false, NavMeshAgent, активная локомоция         │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │ Вход в зону прямой видимости
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 5. L4 (Визуальное представление)                                            │
│    • Подключение 3D-модели (VRM / Mesh), Animator, шейдеры, плашки HUD      │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 3. Зона ответственности Низкого Уровня

* **Задача:** Удерживать в оперативной памяти (L1) вменяемое количество сущностей (например, ~100 из 10 000 существующих в мире).
* **Принцип виртуального размера:** Чем крупнее объект (террейн, макрогород), тем с большей дистанции он стримится из L0 в L1, обеспечивая своевременную готовность фундамента мира.
* **Что низкий уровень НЕ делает:** Не управляет коллайдерами (L2), не включает физику (L3) и не знает про внутренности макро-объектов (квартиры, подъезды).

---

## 4. Макро-объекты и Высокий Уровень

* **Макрогорода и здания:**  
  Низкий уровень поднимает в L1 лоу-поли город и дома поблизости. Высокоуровневая система макрогорода проверяет готовность домов, включает коллайдеры и производит подмену LOD.
* **Синхронные механизмы (платформы):**  
  Комплекс связанных платформ регистрируется как единая макро-сущность с общим радиусом, чтобы их разморозка происходила одновременно и синхронно.
