# Архитектура Загрузки и Барьера Пространственной Синхронизации (Spatial Sync Barrier)

**Проект:** LunaticMagicV3  
**Папка документации:** `Assets/Scripts/md/2026_11_10/`  
**Дата создания:** 10 ноября 2026  
**Назначение:** Описание универсального механизма пространственной синхронизации, разделение сессионной и игровой загрузки, контракт API сущности и логика барьера готовности.

---

## 1. Концепция: Два Уровня Загрузки

Архитектура строго разделяет загрузку на два независимых слоя:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. СЕССИОННАЯ ЗАГРУЗКА (Session Lifecycle)                                  │
│    • Срабатывает ТОЛЬКО при старте игры / загрузке сохранения (F9)          │
│    • Сессия стартует СРАЗУ на паузе: LocalTime.SetPaused(true)               │
│    • Читает профиль, распаковывает сейв в рабочую папку Sessions/{id}/       │
│    • Загружает реестр 10 000 сущностей (ID, координаты, типы)               │
│    • Передаёт эстафету Игровой Загрузке.                                    │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │ Сессия готова в памяти, ждём спавна
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 2. ИГРОВАЯ ЗАГРУЗКА / БАРЬЕР СИНХРОНИЗАЦИИ (Spatial Sync Barrier)           │
│    • Сессия НЕ перезапускается, файлы сейва НЕ трогаются                    │
│    • Срабатывает в трёх ситуациях:                                          │
│      1. Финал сессионной загрузки (первый вход в мир)                       │
│      2. Переход на другую локацию (катсцена двери, портал, подземелье)      │
│      3. Прыжок фокуса за кадр на дистанцию > X (например, > 200 метров)     │
│         (телепорт, вселение в далёкого моба, переключение на напарника)     │
│    • Суть: Пауза времени + экран затемнения + ожидание готовности сущностей │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. API Сущности: Абстракция Синхронизации с Миром

Внутреннее устройство уровней сущности (L1–L4) скрыто внутри неё. Для координатора стриминга сущность выступает как «чёрный ящик» с простым контрактом:

1. **Команда синхронизации:** Координатор говорит сущности: *«Синхронизируй своё состояние относительно текущей точки фокуса и окружения»*.
2. **Событие готовности:** Сущность сама переводит свои внутренние уровни в нужное состояние (грузит меш, настраивает коллайдеры или засыпает) и, когда полностью готова, эмиттит событие: *«Я готова, все мои уровни настроены»*.

### Мини-код контракта:

```csharp
using System;

public interface ISpatialSyncEntity
{
    string EntityId { get; }
    
    /// <summary>
    /// Команда: привести свои уровни (L1-L4) в соответствие с новой точкой фокуса.
    /// </summary>
    void SyncWithWorld(WorldSyncContext context);

    /// <summary>
    /// Событие: сущность рапортует, что все её целевые уровни материализованы и готовы к игре.
    /// </summary>
    event Action<string> OnSyncCompleted;
}

public class WorldSyncContext
{
    public UnityEngine.Vector3 FocusPosition;
    public float DistanceToFocus;
    public bool ForceInstant; // форсировать завершение
}
```

## 3. Координатор Синхронизации (SpatialSyncCoordinator)

Над системой работает надзорный модуль (внутри сессии), который выполняет три задачи:

### Задача 1: Монитор прыжка фокуса
В цикле `LateUpdate` координатор отслеживает дельту смещения точки фокуса:
```csharp
float focusDelta = Vector3.Distance(currentFocusPosition, previousFocusPosition);
if (focusDelta > WarpDistanceThreshold) // например > 200м
{
    TriggerSpatialSyncBarrier(currentFocusPosition);
}
```

### Задача 2: Будим спящих (L0 $\rightarrow$ L1)
Перед запуском опроса координатор определяет список сущностей, попадающих в новую зону интереса:
* Если нужная сущность спит на диске (в L0) — сначала вызывается её принудительное пробуждение в оперативную память (L1): `EntitiesManager.Activate(entityId)`.

### Задача 3: Реестр ожидания и опрос (Countdown Latch)
1. Сессия ставится на системную паузу: `LocalTime.SetPaused(true)`.
2. Показывается экран затемнения (Fade to Black / оверлей загрузки).
3. Формируется временный реестр ожидания:
   ```csharp
   HashSet<string> pendingEntities = new HashSet<string>(targetZoneEntityIds);
   ```
4. Всем сущностям из списка рассылается команда `entity.SyncWithWorld(context)`.
5. По мере готовности сущности присылают `OnSyncCompleted(id)` $\rightarrow$ удаляются из `pendingEntities`.
6. **ФИНАЛ:** Когда `pendingEntities.Count == 0`:
   * Вызывается `Physics.SyncTransforms()` для синхронизации коллизий.
   * Размораживается физика активной зоны (переход целевых тел в L3).
   * Снимается системная пауза: `LocalTime.SetPaused(false)`.
   * Скрывается экран затемнения (Fade In) — игра продолжается!

## 4. Пайплайны ключевых сценариев

### Сценарий А: Загрузка сейва / Новая игра
1. Сессия стартует **СРАЗУ на паузе** (`LocalTime.SetPaused(true)`). Экран загрузки включён.
2. Сессия распаковывает JSON файлы сохранения в `Sessions/{SessionId}/`.
3. Поднимается полный реестр сущностей сессии.
4. Вычисляется начальная точка фокуса (спавн игрока).
5. Запускается опрос сущностей:
   * Будим сущности стартовой зоны из L0 в L1.
   * Отправляем всем команду `SyncWithWorld`.
   * Ждём ответ `OnSyncCompleted` от всех сущностей стартового радиуса.
6. Реестр пуст $\rightarrow$ размораживаем физику $\rightarrow$ `LocalTime.SetPaused(false)` $\rightarrow$ открываем экран игры.

---

### Сценарий Б: Переход на другую локацию (Дверь / Портал)
1. Игрок активирует переход $\rightarrow$ запускается катсцена взаимодействия (фокус на анимации двери).
2. Экран плавно гаснет в чёрный (Fade Out).
3. **Меняем фокус и координаты ДО загрузки:**
   * Перемещаем тело игрока на координаты входа новой локации.
   * `FocusManager.SetFocus(player)`.
   * Точка отсчёта стриминга перемещается на новую позицию.
4. Игра встаёт на паузу (`LocalTime.SetPaused(true)`).
5. Старые далекие сущности отправляются спать.
6. Для сущностей новой локации запускается опрос:
   * Проверяем, что не спят (будим L0 $\rightarrow$ L1).
   * Команда `SyncWithWorld`.
   * Ждём завершения от всех из реестра.
7. Все готовы $\rightarrow$ `LocalTime.SetPaused(false)` $\rightarrow$ Fade In (плавное проявление экрана).

---

### Сценарий В: Резкий прыжок фокуса (> 200 м) или Телепорт
*(Вселение в далёкое существо, переключение на напарника в стиле Baldur's Gate 3, телепорт мага)*:
1. Монитор фокуса детектирует: $\Delta \text{Position} > 200$ м.
2. Экран мгновенно или через быстрый Fade гаснет в тёмный оверлей.
3. Сессия встаёт на паузу.
4. Отрабатывает опрос сущностей целевой зоны (будим L0 $\rightarrow$ L1, отправляем `SyncWithWorld`, ждём готовности).
5. Все отчитались $\rightarrow$ снимаем паузу $\rightarrow$ убираем оверлей. Игрок видит мир глазами новой сущности без просадок FPS и без дыр в террейне.
