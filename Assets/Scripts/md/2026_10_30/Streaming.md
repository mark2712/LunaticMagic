# Стриминг сущностей (Streaming Architecture)

**Проект:** LunaticMagicV3  
**Назначение:** Архитектура стриминга сущностей для одиночной локальной игры на базе Unity `CullingGroup` API.

---

## 1. Архитектурное решение: Unity `CullingGroup` API

Для одиночной локальной игры идеальным инструментом стриминга является встроенный движковый C++ механизм **`CullingGroup`**.

### 1.1. Почему `CullingGroup` идеален для L1–L4
1. **Не требует `GameObject` на L1:**  
   `CullingGroup` работает с обычным плоским C# массивом структур `BoundingSphere[]` (позиция `Vector3` + радиус `float`).  
   Все спящие сущности (L1) живут в оперативной памяти как чистые классы `EntityRuntime`, не создавая лишних объектов и трансформаций в иерархии сцены.
2. **C++ производительность из коробки:**  
   Проверка сфер дистанции выполняется нативно движком Unity с использованием SIMD и многопоточности.
3. **Событийная модель (Event-Driven):**  
   Никаких ручных циклов перебора всех сущностей в `Update()`. Движок сам присылает callback `onStateChanged`, только когда сущность физически пересекает границу зоны.
4. **Frustum Culling (Проверка видимости камеры):**  
   Параметр события `evt.isVisible` бесплатно сообщает, смотрит ли камера на сущность. Если моб в радиусе L4 (20м), но находится за спиной игрока — можно не включать тяжелые анимации лица и мимику до поворота камеры.

---

## 2. Полосы дистанций (Distance Bands) и Маппинг

При инициализации сессии задаются полосы дистанций относительно точки фокуса (игрока):

```csharp
cullingGroup.SetBoundingDistances(new float[] { 30f, 50f, 100f });
cullingGroup.SetDistanceReferencePoint(focusPlayerTransform);
```

| Полоса (Band) | Дистанция | Целевой уровень | Что происходит с сущностью |
| :--- | :--- | :--- | :--- |
| **Band 0** | $0 \dots 30$ м | **L4 (Visuals)** | Подключение VRM 1.0 модели из пула, запуск Animator, визуальное оружие, HUD |
| **Band 1** | $30 \dots 50$ м | **L3 (Active Physics)** | Разморозка физики (`isKinematic = false`), включение NavMesh, локомоция |
| **Band 2** | $50 \dots 100$ м | **L2 (Kinematic Body)** | Легкий `GameObject` с коллайдером (`isKinematic = true`), физическое присутствие |
| **Band 3** | $> 100$ м | **L1 (Pure Data)** | `GameObject` уничтожен/в пуле. Чистые данные `EntityRuntime` в памяти |

---

## 3. Защита от дребезга (Гистерезис)

Если игрок топчется на границе 30 метров (например, 29.9м $\leftrightarrow$ 30.1м), без буфера сущность будет спавниться и удаляться каждый кадр.
Для стабильности применяется **гистерезис (буферная зона 5–6 метров)**:
* **Повышение уровня (L3 $\rightarrow$ L4):** дистанция $\le 30$ м.
* **Понижение уровня (L4 $\rightarrow$ L3):** дистанция $> 36$ м.

## 4. Пайплайн загрузки сейва и синхронизация (Барьер)

Чтобы при старте или загрузке сохранения (F9) сущности не проваливались сквозь недогруженный террейн:

```
                  [ СЕЙВ НА ДИСКЕ ]
                          │
                          ▼
┌──────────────────────────────────────────────────────────────┐
│ ФАЗА 1: Мгновенное C# восстановление Данных (L1)             │
│   • Создаются все EntityRuntime в памяти за 1 кадр           │
│   • Восстанавливаются ID, ХП, квесты, инвентарь, связи       │
│   • Физика Unity выключена, GameObject'ов на сцене нет       │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ ФАЗА 2: Расчет целевых уровней (Target Tiers)                │
│   • Позиция игрока передается в CullingGroup                 │
│   • Мгновенно определяется начальный TargetTier для каждого: │
│     - Фокусная сущность игрока: Target L4                    │
│     - 0..30м: Target L4 | 30..50м: Target L3                 │
│     - 50..100м: Target L2 | >100м: Target L1                 │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ ФАЗА 3: Барьер Синхронизации (Под Loading Screen)            │
│   1. Загрузка террейна и статических коллайдеров сцены       │
│   2. Спавн GameObject для целевых L2/L3 (isKinematic = true) │
│   3. Асинхронная подгрузка 3D-моделей (VRM) для целевых L4   │
│   4. Ожидание завершения всех асинхронных задач видимой зоны │
│   5. БАРЬЕР ПРОЙДЕН: Включение физики (isKinematic = false)  │
│   6. Открытие экрана: Игровой процесс запущен                │
└──────────────────────────────────────────────────────────────┘
```
